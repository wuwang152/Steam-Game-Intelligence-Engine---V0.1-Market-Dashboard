# Steam Game Intelligence Engine V0.1 — Project Report

## 1) Project objective
Steam Game Intelligence Engine V0.1 is a reproducible market-analysis foundation for Steam games data. The project combines a deterministic data-cleaning and feature-engineering workflow with a multi-page Streamlit dashboard so teams can inspect release trends, pricing signals, review dynamics, and genre/tag patterns from a consistent processed dataset.

V0.1 is intentionally scoped as an analytics baseline, not a personalized recommendation product.

## 2) Repository structure
The repository is organized to separate processing logic, application UI, and operational scripts:

- `src/steam_intelligence/`: core cleaning and feature-engineering logic.
- `scripts/`: command-line entrypoints for running the pipeline and validating outputs.
- `app/`: Streamlit dashboard entrypoint and page modules.
- `data/sample/`: reproducible demonstration dataset (`games_sample.csv`).
- `data/raw/`: location for full raw datasets (for example full Steam exports).
- `data/processed/`: generated processed datasets used by the dashboard and downstream checks.
- `tests/`: unit tests for feature behavior and transformations.
- `docs/`: reference documentation.

## 3) Data cleaning pipeline
V0.1 processing is executed through:

```bash
PYTHONPATH=src python scripts/run_pipeline.py --input data/sample/games_sample.csv --output data/processed/steam_games_cleaned.csv
```

Pipeline behavior:

1. Load CSV input.
2. Normalize column names and coerce key numeric fields.
3. Normalize platform flags (`Windows`, `Mac`, `Linux`) into booleans.
4. Remove rows with missing or blank game names.
5. Apply feature engineering.
6. Save deterministic output to `data/processed/steam_games_cleaned.csv`.

The sample dataset is provided for reproducible demonstration. Full raw datasets should be placed under `data/raw/` for complete-scale runs.

## 4) Feature engineering
V0.1 engineered features support market-level analysis:

- **Time feature**: `release_year`.
- **Owner-range parsing**: `owners_low`, `owners_high`, `owners_mid` from `Estimated owners` text ranges.
- **Review volume and quality**: `total_reviews`, `positive_ratio`, `review_signal`, `review_sentiment`.
- **Monetization segmentation**: `price_bucket`.
- **Platform coverage**: `platform_count`.
- **Content metadata density**: `genre_count`, `tag_count`, `screenshot_count`, `movie_count`.

These features are designed for robust aggregation and filtering in dashboard workflows.

## 5) Validation and testing
Data validation command:

```bash
PYTHONPATH=src python scripts/validate_data.py --input data/processed/steam_games_cleaned.csv
```

Validation checks include:

- required schema presence,
- missing/duplicate `AppID` detection,
- non-negative price constraint,
- `positive_ratio` bounded to `[0, 1]`,
- owner range consistency (`owners_low <= owners_high`).

Automated tests:

```bash
PYTHONPATH=src pytest -q
```

The test suite focuses on feature-engineering correctness (owner parsing, ratio logic, bucket/bin behavior, and split-value counters).

## 6) Streamlit dashboard modules
Dashboard launch command:

```bash
PYTHONPATH=src streamlit run app/Home.py
```

V0.1 page modules:

- `Home.py`: overview KPIs, filtering, and core exploration views.
- `1_Overview.py`: high-level market snapshot.
- `2_Release_Dynamics.py`: release-timing distribution views.
- `3_Attention_Distribution.py`: attention/review-oriented distribution analysis.
- `4_Price_and_Monetization.py`: pricing and monetization segmentation.
- `5_Reputation_Signals.py`: review sentiment/signal perspectives.
- `6_Genre_Tag_Explorer.py`: genre and tag exploration.

This report documents module intent from repository structure and code organization; it does not claim local visual verification of dashboard rendering.

## 7) Current limitations
- Owner values are parsed from textual ranges and remain approximations.
- V0.1 relies on rule-based transformations, not model-based inference.
- Data quality depends on upstream raw-field consistency.
- Dashboard modules prioritize foundational exploration over advanced comparative analytics.

## 8) V0.2 roadmap
Planned V0.2 improvements:

1. Expand validation coverage (distribution and outlier guardrails).
2. Add richer dashboard interactions and comparative segment analysis.
3. Improve support for larger full raw datasets under `data/raw/`.
4. Add additional composite market signals (for example hidden-gem or momentum-oriented indicators).
5. Broaden automated test coverage for edge-case parsing and transformations.
